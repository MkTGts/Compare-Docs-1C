# Сверка документов 1С

**Текущая версия: 0.3**


## Назначение

Утилита сопоставляет документы из выгрузки БП и выгрузки реализаций по номеру, сравнивает их суммы и сохраняет Excel-отчет с расхождениями. Приложение имеет графический интерфейс на Tkinter.

## Возможности

- Чтение входных книг Excel форматов `.xls` и `.xlsx` для обеих таблиц. Формат выбирается автоматически по расширению файла.
- Проверка существования файлов, расширений, заголовков, структуры и распознаваемости строк документов с понятными сообщениями об ошибках.
- Сопоставление документов по номеру с игнорированием ведущих нулей и буквенных префиксов номера.
- Формирование файла `.xlsx` с листом «Расхождения».
- Отчет содержит документы с ненулевой разницей, в том числе документы, которые присутствуют только в одной из исходных таблиц.
- Кнопка «Инструкция» открывает краткую справку непосредственно в приложении.

## Требования к входным таблицам

### Таблица БП

- Файл должен быть в формате `.xls` или `.xlsx`.
- Используется первый лист книги.
- В первой строке должны быть заголовки с точным написанием `Номер` и `Сумма`. Столбцы могут располагаться в любом порядке.
- В столбце `Номер` должен быть номер документа, содержащий цифры. Для сопоставления из значения берется первая последовательность цифр, затем удаляются ведущие нули.
- В столбце `Сумма` указывается числовая сумма. Пустая сумма считается нулевой.

### Таблица реализаций («Окт. Реал»)

- Файл должен быть в формате `.xls` или `.xlsx`.
- Используется первый лист книги.
- В столбце B (вторая колонка) должен находиться текст документа, в столбце C (третья колонка) — сумма. Заголовки для этих столбцов не требуются.
- В тексте документа должно встречаться слово `Реализация`, а номер должен находиться непосредственно перед словом `от`, например: `Реализация ... 000123 от 01.01.2026`.
- Пустая сумма считается нулевой. Строки, в которых нет слова `Реализация`, пропускаются.

### Правила сопоставления и отчета

- В номерах удаляются ведущие нули и буквенные префиксы; сравнение выполняется по оставшейся последовательности цифр.
- Суммы сравниваются как числа. Разница округляется до двух знаков после запятой.
- В отчет попадают только записи, у которых разница не равна нулю.
- Если в одной таблице несколько строк с одним и тем же номером, используется последняя встретившаяся строка.
- Отсутствующий документ или сумма при вычислении разницы учитывается как ноль.
- Итоговый файл необходимо указать вручную. Формат результата — `.xlsx`; файл нельзя сохранять поверх одной из входных таблиц.

## Запуск из исходного кода

Нужен установленный Python для Windows. Откройте PowerShell в папке проекта и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements
.\.venv\Scripts\python.exe compare_docs.py
```

Зависимости перечислены в файле `requirements`:

- `openpyxl` — чтение и создание книг `.xlsx`;
- `xlrd` — чтение книг `.xls`;
- `pyinstaller` — сборка приложения в исполняемый файл.

## Сборка одного EXE без консольного окна

Сборку рекомендуется выполнять в виртуальном окружении проекта. Если окружение еще не подготовлено, выполните команды из раздела «Запуск из исходного кода». Затем в PowerShell из папки проекта запустите:

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --onefile --windowed --name SverkaDokumentov compare_docs.py
```

Параметры сборки:

- `--onefile` упаковывает приложение в один исполняемый файл;
- `--windowed` собирает GUI-приложение без консольного окна (эквивалент `--noconsole`);
- `--clean` очищает временные результаты предыдущей сборки;
- `--name SverkaDokumentov` задает имя EXE.

Готовый файл появится здесь:

```text
dist\SverkaDokumentov.exe
```

Передайте пользователю только этот EXE. Python и библиотеки проекта на компьютере пользователя для запуска не нужны. При первом старте приложение может открываться дольше, поскольку PyInstaller распаковывает содержимое сборки во временную папку.

Для повторной сборки выполните ту же команду. Исходный код, виртуальное окружение и папки `build`/`dist` для работы уже собранного приложения не требуются.

## Работа с приложением

1. Нажмите «Выбрать» напротив файла БП и укажите таблицу.
2. Выберите таблицу реализаций.
3. Укажите полный путь и имя итогового файла с расширением `.xlsx` в поле «Сохранить итог» или через кнопку «Выбрать».
4. Нажмите «Запустить сверку».
5. При ошибках проверьте текст сообщения: он указывает файл, строку или ожидаемую структуру. Исправьте источник и запустите обработку повторно.

## Частые проблемы

- **Не удалось прочитать книгу** — проверьте, что файл действительно имеет указанный формат, открывается в Excel и не поврежден.
- **Не найдены заголовки БП** — в первой строке первого листа должны быть заголовки `Номер` и `Сумма` без лишних пробелов и изменений регистра.
- **Недостаточно столбцов в выгрузке реализаций** — добавьте или восстановите столбцы B с текстом документа и C с суммой.
- **Не распознан номер реализации** — проверьте, что номер документа указан перед словом `от`.
- **Не удается сохранить отчет** — укажите существующую папку, расширение `.xlsx` и убедитесь, что файл результата не открыт в Excel.
